# Web debugger integration

The Debugger activity connects this React/Axum workspace to the sibling `chasm-debugger` Python/Rust engine. This is a local development integration across two repositories, not a standalone single-binary debugger distribution.

## Start on Windows

Keep the repositories next to each other as `chasm` and `debugger`. The debugger must already be installed in its `.venv`, with the native REVM extension built. Node.js, Rust and Foundry/Anvil are needed by the web workspace.

From PowerShell:

```powershell
cd "C:\Users\bryan\Documents\source_code\temp\chasm"
npm --prefix ui run build
cargo build
.\target\debug\chasm.exe . --debugger-python "C:\Users\bryan\Documents\source_code\temp\debugger\.venv\Scripts\python.exe"
```

Open http://127.0.0.1:3000 and choose the bug icon, **Debugger**. The Rust binary owns the web launcher. It invokes the configured interpreter with `-I -m chasm_debugger.web_service`, not a `chasm` executable resolved from PATH. The Python CLI has the same public executable name, so use the explicit Rust binary path for the web workspace.

## Offline examples

Two bundled captures are exposed when their files exist in the sibling debugger checkout:

- **Synthetic offline replay**: raw REVERT-prefix/STOP execution, with no Solidity source required.
- **Withdrawal lab (synthetic)**: a compiled `WorkshopVault` with paired build-info. Set a breakpoint at `WorkshopVault.withdraw`, continue, then evaluate `feeBps` or `balances[msg.sender]`.

Both examples use invented chain inputs. The withdrawal lab's reference receipt was generated by the same local engine for UI testing. Neither example is evidence of independently verified historical mainnet execution.

Solidity evaluation discards effects by default. Selecting **Keep**, using **Write locally**, or running a state-changing Yul/allowed `vm.*` command changes only the debugger journal and marks fork experiments diverged. Baseline receipt agreement, the current EVM outcome and worker completion are separate indicators.

The toolbar supports opcode/source stepping, next, finish, continue, run-to and restart where the engine advertises them. **Cancel** terminates the session-owned worker process tree independently of a blocked navigation request. It is not a pause button. A completed or cancelled session cannot be resumed as if still running.

## Sources, resources and local targets

Upload capture/build-info JSON through the launch form. Resources receive server-generated owner-scoped IDs. The browser does not supply arbitrary filesystem read/write paths. Uploads are limited to 8 MiB.

**Load workspace build info** performs an on-demand offline Foundry compiler build and registers an immutable build resource. It retains compiler input/output, source IDs/AST, bytecode/source maps and storage layout. Multiple compilation units require selecting an explicit build-info file. Source attribution still requires runtime parity.

Build generation is serialized to one operation. It is a separate blocking compiler operation and cannot currently be cancelled after it begins. Cancelling a debug session does not cancel this compiler callback.

**Local Foundry** accepts an explicitly trusted workspace-relative `.sol` target with an existing `foundry.toml` inside the workspace. The safe runner does not create project configuration, install libraries, or write build cache/artifacts. It requires an installed compiler. Foundry restart is not advertised by the web service.

The checked-in example target is `examples/debugger/test/WorkshopVault.t.sol`. Arbitrary Python scripts, shell commands, environment/file cheats, signing and FFI are not exposed. Arbitrary Anvil snapshots or chain-31337 transaction replay are not implemented by this integration. Use a local reproduction rather than relabeling one as historical mainnet replay.

## Provider configuration

No public RPC fallback is configured. Online historical replay/fork requires provider aliases mapped by the server environment variable `CHASM_DEBUGGER_PROVIDERS` to environment-variable names that contain endpoint URLs. The browser receives aliases, not credential-bearing URLs. Only the chosen alias is passed to a worker.

Historical engine support remains Ethereum L1 Cancun timestamps `1710338135 <= timestamp < 1746612311`. Current post-Cancun mainnet transactions are outside this support interval. Fork drivers require explicit sender, recipient, nonce, fees and block. All execution and changes remain local and RPC reads are allowlisted. No signing or broadcast is part of the debugger path.

No actual mainnet provider was used during this integration's default verification.

## Session/security behavior

- Loopback server with strict Host/Origin checks on debugger endpoints, including WebSocket.
- HttpOnly SameSite browser-owner cookie and an in-memory CSRF token. No URL/localStorage credentials.
- One active debugger worker per server. Reads and writes are serialized, with generation/revision checks and bounded request-ID history. Duplicate mutation IDs are not replayed.
- HTTP jobs return promptly. WebSocket events and polling recover the latest snapshot without reissuing commands.
- Worker protocol `chasm-web-debugger/1` is private stdin/stdout. Output is framed/bounded and stderr is drained without logging provider secrets.
- Operations have a 60-second supervisor deadline. Unknown outcomes terminate the worker and must not be retried as mutations.
- Worker command-idle cleanup is 10 minutes. Inactive owner/resource cleanup is 30 minutes. Limits include 32 owners, 64 resources/64 MiB, 256 requests per session, and bounded event history.
- Browser debugger mutation never uses the wallet key or the workspace's generic RPC proxy. Existing Anvil workspace state is separate from REVM session state.

The legacy workspace's existing public routes are not a newly hardened remote-access product. Do not expose this development server publicly.

## Native desktop workbench

The native Slint Debugger uses the same owned gateway and isolated worker. Code/Disassembly, Frames/Locals/Arguments, Stack/Memory/Storage/Calldata/Logs/Gas/Last-stop diff and discard-only Solidity evaluation are separated into retained views. Continue, opcode/source stepping, Next, Finish, Run to and Restart are capability/lifecycle gated; the offline preset does not advertise Restart when unsupported. Cancel terminates the worker and retains its last inspection snapshot.

The native launch remains the bundled synthetic WorkshopVault preset. The browser's capture/replay/fork/Foundry launch forms, Keep/mutation controls, and production MCP debugger commands are not automatically available in the desktop. Native state ordering keeps workspace binding, session identity, generation/revision/sequence and local operation tickets distinct. Unknown launch outcomes require reconciliation before another Start; exact-ID cancellation reconciliation can briefly create the first offline worker if the original request never arrived, then disposes it.

See [UI_BRANCH_REVIEW.md](UI_BRANCH_REVIEW.md) for the actual fetched UI revisions and selective-port boundaries. Native layout/input qualification is recorded separately from browser/engine support.

## Delivery boundary

Implemented scope includes the real offline browser-to-engine path, mapped/raw inspection, typed breakpoints/navigation/evaluation/mutation, source/capture resources, safe local Foundry startup, RequestTab/transaction-view launch hooks, provider alias plumbing and lifecycle/security controls.

Not delivered: arbitrary local-Anvil state reconstruction, post-Cancun engine support, macro-result debugger launches, provenance/stack-why UI, remote multi-user hosting, cryptographic RPC-state proofs or independent live-mainnet verification. Source/evaluation restrictions from the engine, including unsupported viaIR/immutable cases, remain explicit capabilities rather than simulated support.
